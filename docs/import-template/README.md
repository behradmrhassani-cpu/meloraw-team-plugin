# قالب ایمپورت

فایل‌های این پوشه قالب ورودی افزونه‌اند. **همه‌ی داده‌ها ساختگی‌اند**؛ داده‌ی واقعی تیم هرگز داخل ریپو نمی‌آید.

| فایل | محتوا |
|---|---|
| `tasks-template.json` | چند تسک نمونه |
| `routines-template.json` | چند روتین نمونه (روزانه، هفتگی، ماهانه) |
| `ideas-template.json` | چند ایده‌ی نمونه |
| `full-template.json` | هر سه با هم |
| `agent-prompt-import.md` | متن آماده برای ایجنت: از روی یک لیست یا توضیح، فایلی دقیقاً به این فرمت بسازد |

قالب خالی (فقط ساختار) و نمونه‌دار از صفحه‌ی «ایمپورت» پنل دانلود می‌شود. فهرست زنده‌ی فیلدها و مقدارهای مجاز: `GET /schema` (با Application Password). این فایل‌ها از روی همان کد ساخته می‌شوند و تست، یکی‌بودنشان را می‌سنجد.

## ساختار فایل
```json
{
  "format": "meloraw-tasks-import",
  "version": 1,
  "tasks": [ … ],
  "routines": [ … ],
  "ideas": [ … ]
}
```
- `format` و `version` را حتماً بنویس. با `format` درست، **فیلد ناشناخته ردیف را رد می‌کند** (تا غلط تایپی دیده شود). فایل قدیمی برد (بدون `format`) فیلد ناشناخته را فقط هشدار می‌گیرد.
- هر سه بخش اختیاری‌اند؛ حداقل یکی لازم است. `comments` و `flags` هرگز وارد نمی‌شوند.
- هر کلیدی که با `_` شروع شود (مثل `_help`) همه‌جا نادیده گرفته می‌شود؛ برای توضیح خودت از آن استفاده کن.
- JSON خالص: بدون کامنت `//`، بدون ویرگول اضافه‌ی آخر، با کوتیشن دوتایی.

## قواعد عمومی
| مورد | قاعده |
|---|---|
| تاریخ | میلادی `YYYY-MM-DD`، روز UTC (مثل `2030-01-15`) |
| زمان‌ها | UTC؛ `created_at` (فقط مهاجرت) به شکل `YYYY-MM-DD HH:MM:SS` و از راه API نادیده گرفته می‌شود |
| حجم فایل | حداکثر ۵ مگابایت |
| تعداد ردیف | حداکثر ۵۰۰۰ ردیف در هر بخش |
| عنوان | حداکثر ۲۵۵ نویسه |
| شرح (`description`) | حداکثر ۲۰۰۰۰ نویسه؛ تگ HTML حذف می‌شود |
| `done_criteria` | حداکثر ۲۰۰۰ نویسه |
| `estimate_minutes` | عدد صحیح، حداقل ۵ و حداکثر ۴۳۲۰۰ دقیقه |
| تکراری | ردیفی که `id` یا (بدون `id`) عنوانش از قبل هست، رد می‌شود؛ تکرار داخل خود فایل هم تکراری است. اجرای دوباره‌ی همان فایل چیزی اضافه نمی‌کند. |
| کد تسک | `MH-1` و مانند آن هنگام ایمپورت **ساخته می‌شود** (پیشوند از مسئول اصلی) و در فایل نیست |

## مقدارهای مجاز
| فیلد | مقدارها |
|---|---|
| `status` | `open` (انجام نشده)، `in_progress` (در حال انجام)، `done` (انجام‌شده) |
| `bucket` | `blocker` (مانع)، `boost` (تقویت)، `normal` (عادی) |
| `priority` | `high`، `med`، `low` |
| `owner` و `assignees` | `you` (محمد)، `maral`، `chakra`، `auto` (اتوماسیون) |
| `kind` (فقط تسک) | `phase` (فاز ثابت)، `new` (تسک تازه) |
| `frequency` (فقط روتین) | `daily`، `weekly`، `monthly` |
| `period_key` (روتین) | روزانه `2026-10-12`، هفتگی `2026-W42`، ماهانه `2026-10` |

## تسک‌ها (`tasks`)
| فیلد | اجباری؟ | توضیح |
|---|---|---|
| `id` | خیر | شناسه‌ی دلخواه تا ۳۲ نویسه (`A-Za-z0-9._-`) برای تشخیص تکراری. نداری؟ تکراری بر اساس عنوان تشخیص داده می‌شود. |
| `title` | **بله** | عنوان |
| `description` | خیر | شرح |
| `owner` | **بله** | مسئول اصلی |
| `assignees` | خیر | فهرست مسئول‌های بیشتر؛ مسئول اصلی همیشه جزوشان است |
| `status` | خیر | پیش‌فرض `open` |
| `bucket` | خیر | پیش‌فرض `normal` |
| `priority` | خیر | پیش‌فرض `med` |
| `kind` | خیر | پیش‌فرض `new` |
| `estimate_minutes` | خیر | نداری؟ تسک «ناقص» وارد می‌شود و بعداً با PATCH پر می‌شود |
| `due_date` | خیر | سررسید |
| `done_criteria` | خیر | معیار انجام |
| `created_at` | خیر | فقط مهاجرت |

## روتین‌ها (`routines`)
| فیلد | اجباری؟ | توضیح |
|---|---|---|
| `id` | خیر | شناسه‌ی روتین (نداری؟ از عنوان ساخته می‌شود) |
| `title` | **بله** | عنوان |
| `description` | خیر | شرح |
| `owner` | **بله** | مسئول اصلی |
| `assignees` | خیر | مسئول‌های بیشتر |
| `frequency` | **بله** | `daily`، `weekly` یا `monthly` |
| `period_key` | خیر | دوره‌ی فعلی؛ نداری؟ دوره‌ی جاری UTC |
| `status` | خیر | وضعیت همین دوره، پیش‌فرض `open` |
| `bucket`، `priority` | خیر | مثل تسک |
| `estimate_minutes` | خیر | زمان تقریبی هر بار اجرا |
| `due_date` | خیر | سررسید |
| `done_criteria` | خیر | معیار انجام |
| `recurrence_until` | خیر | آخرین روز اجرا؛ خالی = بدون پایان |
| `created_at` | خیر | فقط مهاجرت |

## ایده‌ها (`ideas`)
| فیلد | اجباری؟ | توضیح |
|---|---|---|
| `id` | خیر | شناسه (نداری؟ از عنوان ساخته می‌شود) |
| `title` | **بله** | عنوان |
| `description` | خیر | شرح |
| `type` | خیر | مثل `track` یا `sfx` |
| `category` | خیر | دسته |
| `tag` | خیر | برچسب |
| `status` | خیر | پیش‌فرض `open` |
| `created_at` | خیر | فقط مهاجرت |

مالک ایده‌ها همیشه `chakra` است.

## چطور وارد کنیم
1. **پنل:** تسک‌های تیم ← ایمپورت. اول «فقط بررسی کن» را بزن؛ همه‌ی خطاها با شماره‌ی ردیف نشان داده می‌شوند و چیزی ذخیره نمی‌شود. بعد بدون آن تیک.
2. **API:** `POST /wp-json/meloraw-tasks/v1/import?dry_run=1` با بدنه‌ی JSON برای بررسی، و بدون `dry_run` برای ایمپورت واقعی (رمز را از متغیر محیطی بخوان):
   ```bash
   curl -u "$MLT_AUTH" -H 'Content-Type: application/json' --data-binary @full-template.json \
     "$MLT_BASE/import?dry_run=1"
   ```
3. ردیف معیوب رد می‌شود و بقیه وارد می‌شوند؛ گزارش، بخش به بخش `created`، `duplicate` و `invalid` و فهرست خطاها (`section`، `row`، `reason`) را می‌دهد.
